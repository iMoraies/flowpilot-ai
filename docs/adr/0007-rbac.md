# ADR 0007: Role-Based Access Control

## Context

The project needs basic authorization without building a complex permissions engine too early.

## Decision

Use three roles: `ADMIN`, `MANAGER`, and `MEMBER`. Routes use simple guards such as requiring `ADMIN` or either `ADMIN`/`MANAGER`.

## Alternatives Considered

- Granular permissions: rejected because the product surface is still small.
- One boolean admin flag: too limited for near-term user management.
- Attribute-based access control: powerful, but unnecessary complexity for this stage.

## Consequences

RBAC is easy to understand, test, and explain in interviews. The trade-off is less flexibility; if future workflows require custom permissions, this model may evolve into role-permission mapping.
